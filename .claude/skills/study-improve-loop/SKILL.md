# 자율 개선 루프 (5분 학습)

이 스킬은 `docs/rule.md`의 4단계 워크플로 위에서 도는 **반복 유지보수 루프**다. 한 번의 기획→개발이 아니라, 이미 서비스 중인 앱을 계속 점검하고 다듬는 용도다.

## ⚠️ 리뷰 기준 문서에 대한 중요한 주의사항

`docs/planning_document.md`와 `docs/feature_definition.md`는 **v1.0에서 멈춘 스냅샷**이다(F-01~F-10까지만 정의). 반면 실제 코드는 그 뒤로 F-44 이상까지 진행됐고(`grep -rn "// F-[0-9]" src/`로 확인 가능), 특히 `planning_document.md`의 "원칙 1 — 5분 내 완결이 기본값"은 이후 대화에서 **명시적으로 폐기**된 원칙이다(세션 길이를 이유로 기능을 반대하지 않기로 합의됨). 학원(교사/학생) 모드, 스킨, 마스코트 같은 큰 기능군 전체가 이 문서들엔 아예 없다.

그래서 이 문서들을 "코드가 못 따라간 목표"로 그대로 신뢰하면 안 된다. 대신:

1. **더 신뢰할 만한 최신 소스**: 최근 `git log --oneline -50`, 코드 주석의 `F-XX` 표시, `docs/DEVELOPMENT_SUMMARY.md`(있다면), 이 저장소의 auto-memory(`MEMORY.md`)를 문서보다 먼저/함께 본다.
2. `planning_document.md`/`feature_definition.md`에 있는데 코드에 없는 걸 발견해도, 그게 "구현 빈틈"인지 "이미 폐기된 옛 계획"인지 먼저 구분한다 — 애매하면 임의로 판단하지 말고 사용자에게 짧게 확인한다.
3. `docs/architecture_decision.md`는 상대적으로 더 오래 안정적으로 유지돼온 결정(PWA, 프론트엔드 스택, Supabase, Gemini)을 담고 있어 이 문서 대비 코드 정합성 점검은 여전히 유효하다.

## 매 사이클 절차

1. **리뷰 관점**: 위 주의사항을 감안해 `docs/architecture_decision.md` 및 (신중하게) `docs/feature_definition.md`를 실제 구현(`src/`, `supabase/migrations/`, `supabase/seed/`)과 대조한다.
   - 문서에 "결정했다"고 적혀 있는데 코드에 없는 것을 최우선으로 본다.
   - 문서에 아예 없는 새 기능은 이 스킬 안에서 바로 만들지 않는다 — 기능 임의 추가는 금지(rule.md 개발자 역할 금지 사항). 다음 사이클 보고에서 후보로만 언급한다.
   - `docs/english_content_spec.md` 기준 영어 커리큘럼 시드 데이터 공백(예: grammar/vocab/writing의 미완성 Day)도 이 루프가 다룰 만한 항목이다 — 순수 콘텐츠 작업은 기능 임의 추가에 해당하지 않는다.
2. **개발 관점**: 그중 가장 가치 있는 항목 **하나**를 실제로 구현한다. 여러 개를 한 사이클에 욱여넣지 않는다.
3. **검증**: `npx tsc --noEmit`과 `npm run build`를 통과해야 한다. UI가 바뀌었으면 가능하면 실제로 렌더링해 눈으로 확인한다(스크린샷 등). 이 프로젝트엔 자동화된 테스트가 없다 — `study-developer` 스킬의 "참고" 절 확인.
4. **배포/커밋**: 코드가 바뀌었으면 `CLAUDE.md` 지침대로 배포 여부를 묻지 않고 `npm run build && npx wrangler deploy`까지 실행한 뒤 커밋한다. DB 시드/마이그레이션만 추가했다면(코드 변경 없음) 배포는 생략하고, 커밋 메시지에 "Supabase SQL 에디터에서 사용자가 직접 실행 필요"를 명시한다 — 서비스 롤 키가 없어 Claude가 DB에 직접 접근할 수 없다.
5. **보고**: 사이클 결과를 짧은 불릿 요약으로 끝내지 않는다. **어떤 과정으로 이 문제/기회를 발견했는지, 왜 이 방식으로 설계했는지(다른 대안과 비교해서), 코드를 어떻게 이해하면 되는지**까지 설명한다 — 사용자가 그 코드를 남에게 설명할 수 있을 정도로. 오타 수정처럼 사소한 변경까지 이렇게 할 필요는 없지만, 데이터 스키마·알고리즘·UI 전역에 영향을 주는 CSS 규칙처럼 비자명한 로직은 반드시 이렇게 보고한다.

## 루프 지속/중단

`/loop`(dynamic mode)로 실행 중이라면, 사이클이 끝날 때마다 ScheduleWakeup으로 다음 사이클을 예약한다(외부 이벤트를 기다리는 게 아니므로 유휴 틱 기본값 1200~1800초). 더 이상 의미 있게 보완할 게 없으면 멈추고 정리해서 알린다 — 억지로 할 일을 만들어내지 않는다.
