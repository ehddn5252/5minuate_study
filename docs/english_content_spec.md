# 영어 커리큘럼 콘텐츠 명세서

`english_grammar` / `english_vocab` / `english_writing` 세 커리큘럼의 `question_bank` 시드 데이터를
작성할 때 따르는 규칙. 새 Day를 채울 때마다 이 문서 기준으로 작성하고, 규칙이 바뀌면 이 문서부터 갱신한다.

## 0. 현재 진행 상황 (2026-08-20 기준)

| 커리큘럼 | 총 Day | 시드 완료 | 남은 Day |
|---|---|---|---|
| `english_grammar` | 30 | 1~10 | 11~30 |
| `english_vocab` | 30 | 1~10 | 11~30 |
| `english_writing` | 30 | 1~15 | 16~30 |

각 커리큘럼의 Day별 주제(topic)는 `src/data/curriculum.ts`에 이미 30일치가 다 정의돼 있다 —
콘텐츠를 새로 기획할 필요 없이, 정해진 topic에 맞춰 문제만 채우면 된다.

## 1. 파일 구조

- 소스: `supabase/seed/{curriculum}_day{XX}-{YY}.json` — 사람이 검수하기 쉬운 포맷, 5일 단위로 묶는다.
- 배포용: `supabase/seed/{번호}_{curriculum}_day{XX}-{YY}.sql` — Supabase SQL 에디터에 그대로 붙여넣는 `insert into question_bank (...)` 문. 번호는 기존 파일 다음 순번.
- 두 파일은 반드시 **Node 스크립트로 동시에 생성**한다. SQL 문자열의 작은따옴표 이스케이프(`'` → `''`, 한글 따옴표 포함)를 손으로 하면 반드시 실수가 나오므로, 항상 JS 배열을 먼저 만들고 스크립트가 JSON/SQL을 둘 다 뽑아내게 한다. (`gen_writing_11_15.js` 패턴 참고 — 매번 새로 스캐폴딩해도 되고 재사용해도 됨.)

## 2. 하루 분량 구조 (모든 커리큘럼 공통)

Day 하나당 **24문제** = beginner 8 + intermediate 8 + advanced 8.
각 난이도 안에서 **multiple_choice 4개 + short_answer 4개** (2:1이 아니라 1:1인 점 주의 — 실시간 AI 생성 프롬프트의 2:1 비율과는 다르다. 사전 제작 시드는 답을 직접 타이핑해보는 기회를 늘리려고 절반을 단답형으로 둔다).

## 3. 커리큘럼별 문제 패턴

세 커리큘럼은 성격이 달라서 "beginner는 커리큘럼 예문을 그대로 문제로 바꾸고, intermediate/advanced는 새로 쓴다"는 원칙은 같지만 문제 유형 자체가 다르다.

### 3-1. `english_grammar`, `english_writing` (문장 번역/작문형)

`curriculum.ts`의 해당 Day `content`에는 예문 8개가 `• 한국어 문장 → English sentence.` 형식으로 들어있다.

- **beginner (8문제)**: 커리큘럼 예문 8개를 순서 그대로 사용. 앞 4개는 `'{한국어 문장}'를 영어로 옮긴 것은?`형 MC, 뒤 4개는 `'{한국어 문장}'를 영어로 쓰시오.` 형 SA. 새로 문장을 짓지 않는다 — 커리큘럼 내용과 퀴즈가 어긋나면 안 되기 때문.
- **intermediate (8문제)**: 같은 문법 포인트를 다루는 새 문장 8개(4 MC + 4 SA). 일상 대화 수준, beginner보다 어휘·구조를 한 단계 올림.
- **advanced (8문제)**: 같은 문법 포인트를 비즈니스/학술 레지스터 문장으로. 회사·정책·연구·협상 같은 소재를 자주 쓴다(기존 시드 데이터 톤과 통일).

### 3-2. `english_vocab` (단어형)

`curriculum.ts`의 해당 Day `content`에는 단어 10개가 `• word (품사) 뜻 — "example sentence"` 형식으로 들어있다.

- **beginner (8문제)**: 단어→뜻 매칭. MC 6개(`'{word}'의 뜻으로 알맞은 것은?`, 오답은 같은 Day의 다른 단어 뜻들) + SA 2개(`'{word}'의 뜻을 한 단어로 쓰시오.`). 10개 단어 중 8개를 쓰고 2개는 남겨서 intermediate/advanced에서 재사용해도 된다.
- **intermediate (8문제)**: 커리큘럼에 있는 example sentence를 빈칸 채우기로 변형. `"She ___ her goal after years of effort." 빈칸에 가장 알맞은 것은?` 형태. MC 6 + SA 2(단답형엔 힌트로 한글 뜻이나 시제를 괄호로 덧붙임, 예: `(배달하다)`, `(과거형)`).
- **advanced (8문제)**: 동의어 찾기, 유의어 중 의미가 다른 것 고르기(odd-one-out은 **의미 기준**으로만 만든다 — 철자 패턴으로 구별되게 하면 안 됨, 4장 참고), 새 문맥 문장 빈칸 채우기, 뜻→단어 역방향 질문을 섞는다.

## 4. 오답(distractor) 설계 규칙 — 전 커리큘럼 공통

1. **그럴듯한 실수를 반영한다.** 무작위 단어가 아니라 실제로 학습자가 헷갈릴 만한 오류: 잘못된 시제, 전치사 누락/오용, 어순 오류, 관사 누락, be동사·do/does 혼동, 동명사/to부정사 혼동 등.
2. **서식 의존 표현 금지.** "밑줄 친", "굵게 표시된" 같이 화면에 실제로 없는 시각 표시를 가리키면 안 된다. 특정 표현을 지칭해야 하면 문제 텍스트 안에 따옴표로 직접 인용한다. (`src/services/gemini.ts`의 `NO_VISUAL_FORMATTING_INSTRUCTION`과 동일 기준 — AI 생성 문제와 사람이 쓰는 시드 데이터가 같은 규칙을 따른다.)
3. **겉모습 패턴만으로 정답이 드러나면 안 된다.** "다음 중 ~이 아닌 것은?"류 문제에서, 정답 선택지가 나머지 3개와 철자·어미·길이만으로 구별되면 안 된다. 예: 접미사 `-tion` 문제에서 오답 3개만 `-tion`으로 끝나고 정답만 다른 형태면 안 되고, 정답도 `-tion`으로 끝나되 실제로는 그 접미사 규칙이 적용 안 되는 단어(`nation`처럼)를 써야 한다. (`NO_SURFACE_PATTERN_GIVEAWAY_INSTRUCTION`과 동일 기준.)
4. **정답은 정확히 하나.** 복수 정답이 가능하게 애매한 선택지를 넣지 않는다.
5. **선택지 순서는 신경 쓰지 않아도 된다.** 화면에서 렌더링할 때 매번 무작위로 섞으므로(`src/utils/shuffle.ts`), 정답을 항상 첫 번째에 쓰든 무작위로 배치하든 상관없다 — 다만 **`answer` 필드 문자열이 `options` 배열의 항목 중 하나와 정확히 일치**해야 한다(공백·대소문자까지).

## 5. explanation 작성 규칙

- 한 문장, 정답이 왜 맞는지 핵심 문법 규칙만 짚는다. "~이기 때문입니다" 같은 사족 없이 규칙명 위주로.
- 예: `'과거 의문문은 Did+주어+동사원형입니다.'`, `'achieve는 '성취하다'라는 뜻입니다.'`
- 오답에 대한 설명은 넣지 않는다(문제 화면이 정답 하나만 강조하는 UI라 불필요).

## 6. 검증 체크리스트 (커밋 전 필수)

새 Day를 다 쓰면 스크립트로 다음을 기계적으로 검증한다 (`gen_writing_11_15.js` 검증 블록 참고):

- [ ] 문항 수 = Day 수 × 24
- [ ] 각 MC 문제의 `options`가 4개, 전부 서로 다름(`Set` 크기 4)
- [ ] `answer`가 `options` 안에 정확히 존재
- [ ] 같은 Day 안에 완전히 동일한 `question` 문자열 중복 없음
- [ ] `difficulty`별 개수가 8/8/8, 그 안에서 MC/SA가 4/4인지
- [ ] JSON → SQL 변환 후 SQL 파일을 눈으로 한 번 훑어 이스케이프가 깨지지 않았는지 확인(특히 `don't`, `isn't`처럼 아포스트로피가 들어간 영어 문장)

## 7. 배포 절차

1. JSON + SQL 파일을 `supabase/seed/`에 추가.
2. `.sql` 파일 내용을 Supabase SQL 에디터에서 직접 실행 — 이 저장소엔 서비스 롤 키가 없어서 Claude가 대신 실행할 수 없다. 실행은 사용자가 한다.
3. 앱 코드는 변경되지 않으므로 `npm run build && npx wrangler deploy`는 필요 없다(콘텐츠는 DB에서 바로 읽힘).
