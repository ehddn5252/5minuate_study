### F-28: 예측 가능한 틈새 알림 프리셋

**한 줄 설명:** 설정 화면에 "학교 시간표" 프리셋 버튼을 추가해, 등하교·쉬는시간 같은 예측 가능한 틈에 맞춰 알림 시각·방해금지 시간대를 한 번에 채운다.

**페르소나:** 하은(짧고 예측 가능한 틈만 사용 가능), 지호(자습 사이 자투리에 알림이 맞아야 함)

**시스템 처리**
1. 프리셋 선택 시 `quietHoursStart/quietHoursEnd`, `notificationTime` state를 프리셋 값으로 일괄 설정.
2. 기존 F-20 저장 흐름(`updateAppState`, `scheduleLocalReminder`) 그대로 호출.
3. 프리셋은 초기값일 뿐, 이후 수동 수정 시 그 값이 우선.

**동작 규칙**
- 새 저장 필드·스케줄링 로직 추가 없음(F-20 인프라 재사용)
- "적용" 버튼을 눌러야 실제 저장(기존 흐름과 동일)

**검증 조건**
- [ ] 프리셋 탭 시 시각 입력값이 즉시 채워짐
- [ ] 수동 재수정 가능
- [ ] "적용" 없이는 저장 안 됨
- [ ] 적용 후 알림 스케줄 정상 재설정

**기존 기능과의 관계:** F-20의 UI 계층에 프리셋 버튼만 추가. 스키마 변경 없음.

### F-29: 시험일 직접 입력 흐름 (자동 기한 프리필 생략)

**한 줄 설명:** F-33 내신·수능 템플릿 선택 시 `recommendedDays` 기반 자동 기한 계산을 생략하고, 실제 시험일을 직접 입력하도록 유도한다.

**페르소나:** 하은·지호(시험일은 학교가 정하는 강제 일정 — 앱의 "추천 기간"이 실제와 어긋나면 신뢰가 깨짐)

**시스템 처리**
1. `GoalCreateScreen.handleSelectTemplate()`에서 템플릿에 `examScoped: true` 플래그가 있으면 `deadline` 자동 계산 생략.
2. 날짜 입력 필드에 "시험 날짜를 입력하세요" 안내 표시.
3. 나머지 로직(F-01/F-02)은 동일.

**동작 규칙**
- 일반 템플릿은 기존 자동 프리필 유지(회귀 없음)
- 템플릿 선택을 통해서만 트리거됨(직접 입력 경로에는 미적용)

**검증 조건**
- [ ] 내신·수능 템플릿 선택 시 기한 필드가 비어있음
- [ ] 기한 미입력 시 생성 버튼 비활성화(F-01 규칙 유지)
- [ ] 일반 템플릿은 기존처럼 자동 프리필
- [ ] 입력 후 남은 일수·분량 계산은 F-02와 동일

**기존 기능과의 관계:** F-01 프리필 분기에 조건 추가. `Template`에 `examScoped?: boolean` 필드(F-33과 공유).

### F-30: 압박 없는 독려 톤 확장 (동행형 문구)

**한 줄 설명:** 기존 `mateTone`(F-27)을 알림(F-14/F-20)·긴급 배너(F-17) 문구 선택에도 연결한다.

**페르소나:** 하은(부모 잔소리 톤 반발), 지호(추가 압박형 알림이 회피 유발)

**시스템 처리**
1. `MESSAGE_BANK`(F-20)를 단일 배열 → `mateTone`별 배열로 확장. `plain`(기본값)은 기존 5종 유지(회귀 없음).
2. `showReminder()`가 활성 목표의 `mateTone`을 확인해 해당 뱅크에서 문구 선택.
3. `UrgentBanner`(F-17) 고정 문구도 톤별 변형 문구 중 선택하도록 확장.

**동작 규칙**
- 별도 톤 선택 UI 신규 추가 없음(F-27 재사용)
- 비난·압박 표현 금지 원칙 유지
- 여러 활성 목표의 톤이 다르면 알림 대상 목표 자신의 톤을 우선

**검증 조건**
- [ ] `plain` 사용자는 기존과 동일한 문구(회귀 없음)
- [ ] `friendly`/`hype` 목표는 톤에 맞는 문구
- [ ] 새 문구 뱅크에도 비난·압박 표현 없음
- [ ] 알림/배너 화면에 톤 선택 UI 신규 추가 없음

**기존 기능과의 관계:** F-27의 `mateTone`을 F-14/F-17/F-20까지 확장 재사용. F-24(세대 톤 분리, 보류)보다 좁은 범위.

### F-31: "지난 나" 대비 성장 피드백

**한 줄 설명:** 세션 완료 화면에 이번 세션 정답률을 같은 목표의 최근 완료 세션 평균과 비교해 표시한다. 타인·랭킹 비교가 아닌 자기 역사 대비.

**페르소나:** 하은·지호(또래 비교 문화는 강하지만 인앱 랭킹은 비목표 — 안전한 대체 통로 필요)

**시스템 처리**
1. `TestScreen.handleNext()`에서 세션 완료 직후, 같은 `goalId`의 완료 세션 중 최근 N개(예: 5개)의 평균 정답률 계산.
2. 이번 세션과 비교해 상승/유지/하락과 %p 차이 산출.
3. 비교 대상이 3개 미만이면 중립 문구("기록을 쌓는 중이에요") 노출.

**동작 규칙**
- 같은 목표 내 이력만 사용(타인·전체 평균과 비교 금지)
- 하락 시에도 부정적 어휘 없이 중립 표현(예: "오늘은 조금 쉬어가는 날이었어요")
- 세션 완료 화면에 매 세션 1회 노출(F-22 정체성 서사와 노출 시점 다름)

**검증 조건**
- [ ] 이력 3개 미만이면 중립 문구
- [ ] 3개 이상이면 %p 차이 계산·표시
- [ ] 하락 시에도 부정적 표현 없음
- [ ] 타인 데이터 언급 없음

**기존 기능과의 관계:** F-16(기한 대비 진도)과 다른 축. 신규 필드 없이 기존 `Session.quizScore/quizTotal` 이력만 사용.

### F-32: 계속 무료 신뢰 문구

**한 줄 설명:** 목표 생성/설정 화면에 "앞으로도 계속 무료" 안내를 노출하고, 한도 초과 메시지도 유료 전환을 암시하지 않는 톤으로 재확인한다.

**페르소나:** 민준(용돈으로 지출, 무료 지속에 대한 확신 중요), 하은·지호도 간접 수혜

**시스템 처리**
1. `GoalCreateScreen.tsx` 안내 배너에 "완전 무료" 문구 병기.
2. `SettingsScreen.tsx` 계정 섹션에 동일 문구 고정 노출.
3. `LearningScreen.tsx`의 한도 초과 메시지를 "무료라서 있는 하루 제한, 내일 재이용 가능" 뉘앙스로 보강.

**동작 규칙**
- 유료 전환 CTA·가격·프리미엄 언급 일체 금지
- "개인 API 키 설정하기" 버튼은 유지하되 이것이 유료 결제가 아님을 명확히 하는 문구 추가

**검증 조건**
- [ ] 목표 생성 화면에 "계속 무료" 문구
- [ ] 설정 화면 계정 섹션에도 동일 문구
- [ ] 한도 초과 메시지에 유료 전환 암시 없음
- [ ] 가격·구독·프리미엄 UI 없음(회귀 확인)

**기존 기능과의 관계:** 신규 로직 없음, 3개 화면에 카피만 추가.

### F-33: 내신·수능 학습 카테고리 (사용자 정의 시험범위 흐름)

**한 줄 설명:** `templates.ts`에 학년·과목별 내신/수능 템플릿을 신설하되, 고정 day-by-day 커리큘럼이 아니라 기존 topic+rawContent 프리필 흐름을 사용해 사용자가 직접 시험 범위를 입력하게 한다.

**페르소나:** 하은·지호(내신/수능 콘텐츠가 전무한 공백을 메움)

**학년·학교별 진도 편차 처리 방향:** 고정 커리큘럼(`english_grammar`처럼)은 학교 진도와 무관한 콘텐츠에만 적합하다. 내신 시험 범위는 학교·학년·시기마다 달라 고정 day-by-day 데이터는 채택하지 않는다. 대신:
1. 새 템플릿은 `curriculumId` 없이 topic만 프리필(예: "중학교 2학년 국어 내신 대비").
2. `rawContent`(참고자료, 기존 선택 입력)를 핵심 입력으로 격상 — placeholder를 "이번 시험 범위를 붙여넣어주세요"로 문맥화.
3. rawContent 미입력이어도 생성 가능(F-01 규칙 유지), "입력하면 더 정확해져요" 안내만 추가.

**시스템 처리**
1. `templates.ts`에 신규 항목 추가, `examScoped: true` 플래그(F-29와 공유) 부여.
2. 콘텐츠 생성은 기존 `generateGoalContent()` 그대로 호출.
3. `examScoped` 템플릿 콘텐츠는 공유 풀(`contentPool.ts`)에 저장/조회하지 않음(F-21 `practicalMode` 제외 분기와 동일 패턴 — 학교마다 범위가 달라 공유 캐시가 무의미하고 잘못 공유되면 다른 학교 학생에게 부정확한 정보가 노출될 위험).

**동작 규칙**
- 고정 커리큘럼 데이터 신설 안 함
- 학년별로 개별 템플릿 등록(학년 묻는 새 입력 필드 없음, 템플릿 선택 자체로 구분)
- 민준을 겨냥한 신규 템플릿은 만들지 않음(기존 템플릿+톤 조정으로 충분)

**검증 조건**
- [ ] 새 템플릿은 topic+rawContent 프리필 흐름으로 생성(고정 커리큘럼 아님)
- [ ] rawContent placeholder가 "시험 범위 입력" 문맥으로 변경
- [ ] 이 템플릿 콘텐츠는 공유 풀에 저장 안 됨
- [ ] 학년별 별도 템플릿 존재, 학년 질문 UI 없음
- [ ] rawContent 미입력 상태로도 생성 완료(회귀 없음)

**기존 기능과의 관계:** F-01/F-02 재사용, 신규 프롬프트 로직 없음. `Template`에 `examScoped?: boolean` 필드(F-29와 공유). 공유 제외 분기는 F-21 패턴 재사용.

### F-34: 보호자 공유용 문구 프리셋

**한 줄 설명:** 완료 화면의 공유하기에 대상 선택(보호자/친구)을 추가해, 이미지·통계는 그대로 두고 텍스트만 대상에 맞게 바꾼다.

**페르소나:** 하은·지호(부모의 학습 개입 가능성 — 단, 대시보드는 비목표이므로 공유 카드 수준으로 제한)

**시스템 처리**
1. `shareCard.ts`의 `shareOrDownload()`에 `audience?: 'parent' | 'general'` 파라미터 추가.
2. 이미지(캔버스)는 대상 무관 동일 유지.
3. `navigator.share()`의 `text`만 대상별 분기 — 보호자용은 성적 강조 대신 꾸준함 강조.

**동작 규칙**
- 이미지 통계 항목(스트릭/점수/퍼센트)은 대상 무관 동일 — 오답 목록·학습시간 등 신규 상세 데이터 추가 금지(부모 대시보드 비목표 침범 금지)
- 보호자용 텍스트는 성적·석차 강조 없이 "꾸준함/과정" 중심 고정
- 대상 선택 UI는 버튼 2개 수준, 별도 화면 없음

**검증 조건**
- [ ] 공유 버튼 탭 시 대상 선택지 표시
- [ ] 두 대상 모두 동일한 이미지
- [ ] 보호자 선택 시 꾸준함 중심 문구
- [ ] 기존에 없던 정보(오답/학습시간 등) 신규 노출 없음

**기존 기능과의 관계:** `shareOrDownload()` 파라미터 확장, 완료 화면 버튼 핸들러 확장. 신규 인프라 없음.
