## 0. 현재 구현 확인 결과 (신규 기능 설계의 전제)

| 확인 항목 | 실제 상태 | 신규 기능 설계에 미치는 영향 |
|---|---|---|
| 스트릭 계산 (`TestScreen.tsx`) | 어제 완료 세션이 없으면 스트릭이 **1로 강제 리셋**. 목표별 개별 관리, 최고기록 별도 보존. | F-18이 리셋 조건에 예외 규칙 추가 |

| 퀴즈 진행 상태 (`TestScreen.tsx`) | 문항별 정답 여부는 컴포넌트 로컬 state에만 존재. 세션엔 `dailyQuizIds`와 최종 `quizScore/quizTotal`만 저장. 중간 저장 없음 — 앱을 닫았다 열면 처음부터 다시 풀어야 함. | F-19/F-23이 채워야 할 실제 공백 |
| "다음 학습 계속하기" (`HomeScreen.tsx`) | 오늘 세션 완료 시 다음 날짜(`completedSessions+1`) 학습으로 즉시 진입 가능. | F-23은 "완료 후 다음 날"이 아니라 "진행 중 중단 후 재개"로 확장 |
| 학습 자료 화면 (`StudyMaterialsScreen.tsx`) | 커리큘럼/노트/메모 3탭. 실무 연계 콘텐츠 섹션 없음. | F-21은 화면 추가가 아니라 `gemini.ts` 프롬프트 변경 |
| 목표 완료 화면 (`GoalCompleteScreen.tsx`) | 점수/스트릭 요약 중심. 정체성 서사 카피 없음. | F-22는 완전 신규 카피 레이어 |
| 난이도 시스템 (`QuizLevel`) | 콘텐츠 난이도만 조절, 톤/문체는 조절 안 함 | F-24는 별개 축(톤)이라 신규 필드 필요 |
| 공유 콘텐츠 풀 (`contentPool.ts`, Supabase `shared_content`) | 캐시 키가 `templateId + dayNum` 기준 — 세그먼트 무관 전체 공유 | F-24 콘텐츠까지 분리하려면 스키마 변경 필요(범위 밖) |

### F-18: 유연한 학습 리듬 관리 (스트릭 완화)

**한 줄 설명:** 하루 세션을 놓쳐도 스트릭이 전부 무너지지 않도록, 목표별로 제한된 횟수의 "리듬 유지권(프리즈)"을 자동 적용한다.

**페르소나:** 민석(회식·야근으로 무너지면 재도전 포기), 지은(예측 불가한 중단이 죄책감으로 이어짐)

**시스템 처리**
1. 세션 완료 판정 시점(`TestScreen.tsx` 스트릭 계산)에서, 어제 완료 세션이 없으면 목표별 `streakFreezeRemaining` 잔여 개수를 확인한다.
2. 잔여가 있으면 스트릭을 유지하고 잔여를 1 차감한다. 없으면 기존대로 1로 리셋한다.
3. 프리즈는 목표 생성 시 일정 개수 지급, 이후 주기적으로 재충전된다.

**동작 규칙**
- 자동 적용(사용자가 끄거나 아낄 수 없음, 입력 최소화 원칙 유지)
- 프리즈로 유지된 스트릭도 뱃지(`flame_7`, `persistence_30`) 판정에 정상 반영

**검증 조건**
- [ ] 프리즈 잔여 있을 때 하루 건너뛰어도 스트릭 유지
- [ ] 프리즈 소진 후 미완료 시 정상 리셋
- [ ] 사용 시 "리듬 유지권 사용됨" 1회 표시
- [ ] 뱃지 판정 정상 적용

**기존 기능과의 관계:** F-15(연속 달성 스트릭) 리셋 조건에 예외 분기 추가. `Goal`에 `streakFreezeRemaining` 필드 추가.

### F-19: 자투리 시간 최적화 (조각 세션)

**한 줄 설명:** 오늘 세션(요약+퀴즈)이 여러 번 끊겼다 이어져도 마지막 지점부터 정확히 재개된다.

**페르소나:** 지은(세션 도중 강제 중단 빈번), 민석(출퇴근 중 끊김)

**시스템 처리**
1. `Session`에 진행 위치 필드(`currentQuizIndex`, `quizAnswers[]` 등) 추가, 문항 제출마다 즉시 저장.
2. 재진입 시 저장된 위치부터 화면 복원(정오답 표시 유지).
3. 세션 완료 시 진행 위치 필드 초기화.

**동작 규칙**
- 자정을 넘기면 미완료 진행 폐기, 새 세션으로 전환(F-07과 일관)

**검증 조건**
- [ ] N번째 문항까지 풀고 종료 후 재진입 시 N+1번째부터 이어짐
- [ ] 이미 답한 문항 정오답 표시 유지
- [ ] 자정 경과 후 새 세션 전환

**기존 기능과의 관계:** F-08 재개를 화면 단위 → 문항 단위로 세분화. F-23과 데이터 모델 공유(짝 기능).

### F-20: 조용하고 절제된 동기부여

**한 줄 설명:** 알림 문구를 자기연민 허용형 톤 뱅크로 다양화하고, 사용자가 설정한 "방해 금지 시간대"에는 알림을 보내지 않는다.

**페르소나:** 지은(가족 시간 침범 시 신뢰 붕괴), 민석(압박형 톤이 회피 유발), 현우(존중하는 어조 필요)

**시스템 처리**
1. `showReminder()` 발송 직전 방해 금지 시간대 확인, 포함되면 시간대 종료 시점으로 당일 내 재스케줄.
2. 알림 문구를 고정 1종 → 톤이 다른 문구 뱅크(3~5종)로 확장, 연속 미완료 일수에 따라 선택.
3. 긴급 독려(F-17) 문구도 동일 공감형 톤 뱅크 사용.

**동작 규칙**
- 방해 금지 시간대는 전역 설정(appState)
- 시간대 종료 후에도 이미 완료했으면 미발송(F-14 규칙 유지)

**검증 조건**
- [ ] 방해 금지 시간대 내 미발송
- [ ] 시간대 종료 후 재발송(단, 완료 시 미발송)
- [ ] 문구가 매번 다르게 노출
- [ ] 압박 표현 없음

**기존 기능과의 관계:** F-14 발송 조건/문구 로직 확장. 새 알림 인프라 불필요.

### F-21: 실무 연계형 학습 콘텐츠

**한 줄 설명:** 목표 생성 시 "실무 연계 강조" 토글로, 요약·퀴즈 해설에 실무 적용 예시 1줄을 포함시킨다.

**페르소나:** 민석("회사에서 바로 쓸 수 있겠다"는 실감), 현우(실무·면접 연결 확신)

**시스템 처리**
1. 토글 ON 시 `gemini.ts` 프롬프트에 "요약/해설에 실무 적용 예시 1줄 포함" 지시 추가.
2. 응답 JSON 스키마는 변경 없음(텍스트 내용만 변화).
3. 실무 연계 모드 콘텐츠는 공유 풀(`contentPool.ts`)에 저장/조회하지 않음(개인화 콘텐츠).

**동작 규칙**
- 목표 단위로 고정(세션마다 토글 불가)
- 커리큘럼 원문 자체는 변경하지 않고 부가 설명에만 적용
- 요약 항목 수 상한(7개) 유지

**검증 조건**
- [ ] 토글 ON 시 실무 예시 포함
- [ ] 토글 OFF 시 기존과 동일(회귀 없음)
- [ ] 실무 연계 콘텐츠는 공유 풀 미저장
- [ ] 요약 항목 7개 이하 유지

**기존 기능과의 관계:** F-08·F-11 콘텐츠 생성 프롬프트 확장. `Goal`에 boolean 필드 1개 추가.

### F-22: 정체성/성장 서사 강화

**한 줄 설명:** 목표 완료·주요 마일스톤 시 "당신은 이제 ~할 수 있는 사람입니다" 형태의 정체성 문장을 제공한다.

**페르소나:** 현우(매일의 누적이 "무엇이 되어가는가"로 보여야 함), 민석·지은도 간접 수혜

**시스템 처리**
1. 1단계(권장 시작점): 주제 텍스트 기반 클라이언트 템플릿 문장("이제 나는 {topic}을(를) 실무에 적용할 수 있는 사람입니다") 생성 — Gemini 호출 추가 없음.
2. 목표 완료 화면(`GoalCompleteScreen.tsx`)과 7일/30일 스트릭 마일스톤에 노출.
3. 세션 완료 화면(매일)에는 노출하지 않음(피로도 방지).

**동작 규칙**
- 문장은 사용자가 수정 불가
- 과장된 성취 표현 대신 실행 능력 중심 표현으로 제한

**검증 조건**
- [ ] 목표 완료 시 정체성 문장 표시
- [ ] 마일스톤 달성 시 동반 노출
- [ ] 세션 완료 화면엔 매번 노출 안 됨
- [ ] 과장 표현 없음

**기존 기능과의 관계:** F-04·F-15 완료/마일스톤 화면 카피 레이어 확장. 1단계는 순수 클라이언트 템플릿(인프라 변경 없음).

### F-23: 중단-재개 친화적 경험 (세션 내부 재개)

**한 줄 설명:** 세션의 어느 지점에서 이탈해도 홈 화면에 "이어하기" 상태가 명시적으로 표시되고 정확한 지점으로 복귀한다.

**페르소나:** 지은(중단 빈번), 민석(다음날 아침 이어가는 패턴)

**시스템 처리**
1. F-19의 진행 위치를 `HomeScreen.tsx`의 `GoalCard`가 조회해 "이어하기 (N/M 문항)" 상태를 우선 표시.
2. 탭 시 퀴즈의 저장된 지점으로 바로 진입.
3. 완전 미시작 상태면 기존 F-07 동작 유지.

**동작 규칙**
- 버튼 라벨 3단계 구분: "오늘 학습 시작"(미시작) / "이어하기 · N/M 문항 남음"(중단 후) / "다음 학습 계속하기"(당일 완료 후)
- 자정 경과 시 폐기, 새 세션 전환(F-19와 일관)

**검증 조건**
- [ ] 퀴즈 도중 이탈 후 "이어하기 · N/M 문항 남음" 표시
- [ ] 탭 시 저장 지점으로 정확히 진입
- [ ] 미시작 상태는 기존과 동일
- [ ] 자정 경과 후 상태 사라짐

**기존 기능과의 관계:** "다음 학습 계속하기"(날짜 단위)의 세션 내부(문항 단위) 확장. F-19와 데이터 모델 공유, 짝 기능.

### F-24: 세대 톤 분리

**한 줄 설명:** 정오답 피드백·독려·완료 메시지를 세대별 톤(담백/캐주얼)으로 분리한다.

**페르소나:** 현우(20대向 톤과 섞이면 "나이 든 학생" 취급 느낌)

**동작 규칙**
- 톤 분리는 문구(카피)에만 적용, 학습 콘텐츠 자체는 분리하지 않음(공유 풀 효율성 유지)
- 쇼츠 화면은 마케팅 퍼널 목적상 항상 캐주얼 톤 유지(로그인 전 화면, 개인화 불가 예외)
- 나이를 직접 묻는 질문은 만들지 않음

**검증 조건**
- [ ] 톤 변경 시 피드백/독려/완료 문구 즉시 반영
- [ ] 미선택 시 기본(차분) 톤 적용
- [ ] 학습 콘텐츠 자체는 톤과 무관하게 동일
- [ ] 쇼츠 화면은 항상 캐주얼 톤

**기존 기능과의 관계:** F-12·F-14/F-17·F-04 문구 레이어 횡단 확장. **본 명세는 저비용(문구만 분리) 버전을 기본 스코프로 함.**

## 우선순위 — 현재 스택 기준 구현 난이도 낮은 순

| 순위 | 기능 | 난이도 근거 |
|---|---|---|
| 1 | F-18 유연한 학습 리듬 관리 | 순수 클라이언트 로직, `TestScreen.tsx` 스트릭 분기 + `Goal` 필드 1개. 새 화면·API·스키마 없음 |
| 2 | F-20 조용하고 절제된 동기부여 | `notification.ts`/`SettingsScreen.tsx`/`appState`만 변경. 문구 뱅크는 정적 배열 |
| 3 | F-19 + F-23 (세트) | `Session` 필드 추가 + `saveSession` 호출 지점 확대 + `HomeScreen.tsx` 분기. 여러 화면 걸쳐 3순위 |
| 4 | F-22 정체성/성장 서사 (1단계 템플릿) | 카피만 추가하는 수준으로 쉬움 |
| 5 | F-21 실무 연계형 콘텐츠 | 프롬프트 변경 + 공유 풀 제외 분기 추가로 F-22보다 약간 더 손이 감 |

**보류/후순위:** F-24는 앱 전역 텍스트 렌더링 지점을 모두 건드려야 해서 범위가 가장 넓음. 1차 착수 후보에서 제외.

### 1차 착수 후보
1. F-18 — 유연한 학습 리듬 관리
2. F-20 — 조용하고 절제된 동기부여
