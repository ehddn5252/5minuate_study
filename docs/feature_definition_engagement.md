### F-40: 완료 화면 축하 연출 확장 (컨페티·카운트업·햅틱·사운드)

**한 줄 설명:** `SessionCompleteScreen.tsx`/`GoalCompleteScreen.tsx`의 `animate-bounce` 하나뿐인 축하를 캔버스 기반 자체 구현 컨페티, `navigator.vibrate` 햅틱, Web Audio API 생성 효과음으로 확장한다. 전부 opt-out 가능.

| 항목 | 내용 |
|---|---|
| 근거(방향) | Planner 6.6 |
| 위치 | 신규 `src/utils/celebration.ts`(컨페티/사운드/햅틱), `SessionCompleteScreen.tsx`/`GoalCompleteScreen.tsx` 마운트 시 1회 호출. Opt-out 토글: `SettingsScreen.tsx`의 기존 "알림 허용" 토글(183~195행)과 동일한 스위치 UI 패턴 재사용 |
| 데이터 모델 변경 | `AppState.celebrationEffectsEnabled?: boolean`(기본 true) 추가 |
| **신규 의존성 트레이드오프** | `package.json`에 애니메이션/사운드 라이브러리가 전무함(0번 표). `canvas-confetti` 같은 라이브러리는 gzip 4~5KB로 작지만, 이 프로젝트 최초의 "장식성" 의존성이 됨. Cloudflare Workers 정적 배포 + PWA 오프라인 캐싱 환경에서는 번들에 새 청크가 생기고 서비스워커 캐시 목록에도 추가돼야 함. 반면 컨페티는 파티클 50~80줄 수준의 캔버스 코드로 직접 구현 가능하고, 사운드(Web Audio `OscillatorNode`)와 햅틱(`navigator.vibrate`)은 브라우저 내장 API라 의존성이 아예 없다. **FO 권장: 신규 npm 패키지 추가하지 않고 직접 구현.** |
| 충돌 검토 | (1) F-37 레벨업 타이머 연장 이슈와 동일 지점 공유 — 컨페티 재생 시간도 타이머 내로 캡. (2) 컨페티 캔버스는 `pointer-events: none`으로 두 공유 버튼·"홈으로 가기" 버튼 클릭을 가리면 안 됨(220~152행, 138~143행 버튼 영역). (3) iOS Safari는 `navigator.vibrate` 미지원 — feature-detect 후 무음 no-op 처리 필수(에러 방지) |
| 5분 완결 검토 | opt-out 가능해야 하며(Planner 제외 방향 "사운드·진동 강제 ON 금지"), 끄면 완전히 이전 화면과 동일하게 작동(회귀 없음) |

## 1. 구조적 이슈 — 반드시 FO/디자인 단계에서 해소 필요

1. **완료 화면 자동 이동 타이머와 신규 연출의 충돌** — `SessionCompleteScreen.tsx`(4초)·`GoalCompleteScreen.tsx`(6초)는 애니메이션 완료와 무관하게 고정 발동한다. F-37(카운트업/레벨업)·F-40(컨페티)이 이 타이머보다 길게 재생되면 화면이 중간에 잘려 보인다. → 평소 세션은 타이머를 바꾸지 않고(회귀 없음), 레벨업 등 드문 순간에만 짧게 캡을 두고 연장 + 탭하면 즉시 스킵 가능하게 처리할 것을 F-37에 명시했다.
2. **완료 화면 조건부 블록 과밀** — 이미 `usedFreeze`/`isStreakMilestone`/`newBadges`/`growthFeedback` 4개 조건부 블록이 있는데, 이번 제안으로 XP/레벨업(F-37), 마스코트(F-38), 깜짝 보상(F-39), 자기최고기록 강조(F-41), 스트릭 위기 강화(F-42)까지 겹치면 한 화면에 최대 9개 요소가 동시에 뜰 수 있다. F-22가 이미 "정체성 서사는 매일 노출하지 않고 마일스톤에서만" 노출해 피로도를 관리한 선례가 있으므로, 구현 단계에서 **노출 우선순위/최대 노출 개수 규칙**을 정해야 한다(예: 그날 가장 중요한 이벤트 1~2개만 강조 노출, 나머지는 조용히 생략). 이 문서는 각 기능의 트리거 조건만 정의하고, 화면당 동시 노출 규칙은 구현 단계 과제로 남긴다.
3. **iOS Safari `navigator.vibrate` 미지원** — F-40 햅틱은 feature-detect 없이 호출하면 에러가 나지 않지만 조용히 무시되므로 문제는 없으나, 명시적으로 처리 여부를 확인해야 함(§F-40 참고).
