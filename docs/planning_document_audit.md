## 1. 현재 제품 스냅샷

### 1.1 규모
- 화면(Route) 18개: `/` `/goals` `/goals/create` `/goals/edit/:goalId` `/learn/:goalId` `/test/:goalId` `/complete/:sessionId` `/goal-complete/:goalId` `/wrong-pool` `/retry/:goalId` `/my-questions` `/calendar` `/recordings` `/achievements` `/materials/:goalId` `/shorts/:templateId` `/settings` `/`(로그인 전)
- `src/screens` + `src/components` + `src/utils` 합산 약 5,549줄 (screens 18개 파일 기준, wc -l 실측)
- 기능 번호 F-01~F-42까지 5개 기능정의서 문서에 명세 완료. **단, 코드에는 F-43(알림 프리셋 확장 주석 "F-28/F-43"), F-44(생성할 문제 수 선택), F-46(음성 답변 녹음, `RecordingsScreen.tsx`)이 이미 구현돼 있으나 어떤 `feature_definition*.md`에도 없음.** 목표 삭제(`deleteGoalCascade`, `GoalListScreen.tsx`)도 문서화되지 않은 채 구현됨. → **기능정의서가 실제 코드보다 최소 1개 릴리스 뒤처진 상태(문서 부채)**. 이번 감사는 이 미문서화 기능들도 코드 실사로 포함해 다뤘다.

### 1.2 하단 탭(핵심 내비게이션) 4개
`홈(오늘의 학습)` · `목표(목록/생성/수정/삭제)` · `업적(뱃지)` · `설정`
그 외 화면(오답 목록/내 문제집/녹음 모음/캘린더)은 설정 화면 또는 홈 화면 헤더 아이콘을 통해서만 도달하는 2차 내비게이션.

### 1.3 핵심 플로우
1. **목표 생성** (`GoalCreateScreen`) — 템플릿 선택 또는 직접 입력. 주제+기한(필수) 외에 난이도/문제 수(5·10·15·20개)/AI 말투(3종)/실무연계 토글/참고자료(선택) 총 6개 입력 지점.
2. **오늘의 학습** (`HomeScreen` → `LearningScreen`) — 요약 열람.
3. **테스트** (`TestScreen`) — 퀴즈 응답, 오답은 오답 풀에 누적.
4. **세션 완료** (`SessionCompleteScreen`) — 점수/스트릭/정답률 + 조건부 블록 다수(§3.3 참고) + 공유 2종.
5. **목표 완료** (`GoalCompleteScreen`) — 정체성 서사 + 유사한 조건부 블록 세트.
6. 부가: 오답 목록/다시풀기, 내 문제집(북마크), 녹음 모음, 캘린더, 업적, 설정(알림 프리셋·방해금지·축하효과 on/off·고객센터).

### 1.4 자유 예산 상태
결제·구독·유료 UI 0건 확인. Cloudflare Worker 프록시로 API 키 불필요, 하루 20회 IP 기준 한도. 신규 npm 의존성도 F-40에서 의도적으로 회피(캔버스 직접 구현). 1인 무보수 유지보수라는 제약은 지금까지 잘 지켜지고 있음.

## 2. 추가 후보 (신규 기능) — 5개

기준: "듀오링고에 있으니까"가 아니라 **1인 개발자가 무료로 유지 가능하고, 핵심가치("포기 안 하게 만들기")에 직접 기여하는가**로만 선별했다. 화려한 기능은 의도적으로 배제했다.

### A-1. 목표 "중단 → 재개" 허용 (F-05 정책 재검토)
**무엇을**: 현재 `GoalListScreen`에서 진행 중 목표를 "중단"하면 상태가 `inactive`로 바뀌고, `feature_definition.md` F-05 동작 규칙에 "비활성화된 목표는... 재활성화는 지원하지 않는다"고 명시돼 있으며 코드도 이를 그대로 따른다. 실수로, 혹은 며칠 쉬고 싶어서 중단을 눌렀는데 되돌릴 방법이 없다.
**왜**: 앱의 핵심가치는 "목표 설정을 하면 목표를 절대 포기하지 않게 하기"다. 그런데 정작 사용자가 잠깐 멈추고 싶을 때 앱이 "돌아올 길"을 원천 차단하는 것은 핵심가치와 정면으로 상충한다. 새 목표를 처음부터 다시 만들게 하는 것보다, 중단된 목표를 재개(스트릭은 리셋되더라도 진행률/기한은 유지)할 수 있게 하는 편이 이탈 방지에 더 직접적으로 기여한다.
**비목표 충돌 검토**: 없음. 소셜/통계/구독과 무관, 순수 상태 전이 로직(`status: 'inactive' → 'active'`) 1개 추가로 충분. 1인 유지보수 부담 낮음.

### A-2. PWA 홈 화면 설치 유도
**무엇을**: `manifest.json`/설치 프롬프트를 통해 "홈 화면에 추가"를 가볍게 유도(예: 3번째 방문 시 1회 배너).
**왜**: 이 앱의 재참여 전략은 전부 "알림이 사용자를 다시 데려온다"는 F-14/F-20에 의존한다. 하지만 브라우저 탭을 다시 찾아 열어야 하는 마찰 자체가 이탈 지점이다. 홈 화면 아이콘 하나가 "오늘 학습 시작"까지의 탭 수를 줄여 "시작 마찰 제로" 원칙(F-07)을 강화한다.
**비목표 충돌 검토**: "오프라인 퍼스트 설계 금지"와는 다른 층위(오프라인 없이 아이콘만 추가). 무료, 신규 서버 인프라 불필요.

### A-3. 5분 카운트다운 시각 표시
**무엇을**: `LearningScreen`/`TestScreen`에 "약 5분" 텍스트 대신(또는 병행) 실제로 흘러가는 카운트다운/카운트업 타이머를 작게 표시.
**왜**: "공부 및 테스트를 5분 안에 진행 가능하게 하기"가 이 제품의 유일한 성공 기준(ceo_prompt.md)인데, 정작 화면에는 "약 5분"이라는 고정 텍스트만 있고 실제로 5분 안에 끝난다는 걸 사용자가 체감할 장치가 없다. 타이머는 이 약속을 시각적으로 증명해 신뢰를 쌓는다.
**비목표 충돌 검토**: 시간 제한을 강제하는 게 아니라(F-12 "시간 제한은 없다" 유지) 경과 시간만 보여주는 정보성 UI. 신규 의존성 없음(순수 `setInterval`).

### A-4. 다중 목표 시 "오늘 할 일" 원탭 자동 추천
**무엇을**: 진행 중 목표가 2~3개일 때 `HomeScreen`에 카드를 전부 나열하는 대신, 가장 급한 목표(마감 임박/지연 중) 하나를 상단에 크게 띄우고 "오늘 학습 시작"을 원탭으로 처리. 나머지는 접어서 보여줌.
**왜**: "게으른 사람"을 위한 앱에서 목표 3개가 동시에 카드로 나열되면 오늘 뭘 먼저 할지 고르는 것 자체가 선택 마찰이다. F-07의 "시작 마찰 제로 원칙"을 다중 목표 상황까지 일관되게 적용하는 확장.
**비목표 충돌 검토**: 없음. 기존 `UrgentBanner` 로직(지연 판정)을 재사용해 정렬 기준만 추가하면 됨. 심층 분석 아님(단순 정렬).

### A-5. 오답 풀 잔존 범위 재확인 및 정정
**무엇을**: 코드 확인 결과 `WrongPoolScreen.tsx`은 `goals.filter(g => g.status === 'active')`로 활성 목표만 순회한다. 즉 목표를 "중단"하거나 "완료"하는 순간 그 목표의 오답 문항은 오답 목록 화면에서 즉시 보이지 않게 된다(데이터 자체는 남아있을 가능성이 높지만 조회 경로가 끊김). 완료된 목표의 오답도 계속 복습하고 싶은 사용자를 위해 필터를 `active`뿐 아니라 `completed`까지 포함하도록 수정.
**왜**: "오답을 부드럽게 다시 보여준다"는 F-13/F-30의 취지가 목표 완료 직후부터 조용히 깨지는 구조적 결함에 가깝다. 신규 기능이라기보다 기존 기능의 범위 버그에 가까우나, 사용자 체감상 "내 오답이 사라졌다"로 인식될 수 있어 추가 후보로 명시.
**비목표 충돌 검토**: 없음. 필터 조건 한 줄 수정 수준.

## 3. 제거/축소 후보 (가지치기)

### P-1. 목표 생성 화면의 옵션 과잉 — **확신도: 상**
**원래 의도**: 난이도(F-01 기존), 문제 수(F-44), AI 말투(F-27), 실무연계(F-21)는 각각 독립된 세그먼트 리서치(10대/20대/30대)에서 개별적으로 타당성이 검증된 기능이었다.
**재검토 사유**: `GoalCreateScreen.tsx`를 실사한 결과 목표 하나를 만들 때 사용자가 결정해야 하는 항목이 **주제, 기한, 난이도(3택), 문제 수(4택), AI 말투(3택), 실무연계 토글, 참고자료** 총 7개다. 그런데 `feature_definition.md` F-02 동작 규칙은 명시적으로 "하루 학습 분량은 5분 완결 기준으로 자동 조율된다. **사용자가 분량을 직접 늘리거나 줄이는 설정은 제공하지 않는다**"고 못박고 있다. F-44(문제 수 선택: 5/10/15/20개)는 이 원칙을 정면으로 위반하며 구현됐다 — 각 기능은 개별적으로는 타당했지만 누적되며 원래 "입력 최소화 원칙"(F-08)을 무너뜨렸다. "게으른 사람"이 목표 하나 만들려고 7개 선택지를 거쳐야 하는 것 자체가 핵심가치와 상충.
**권장 방향(FO 재검토용)**: 문제 수 선택은 기본값(5개)만 남기고 UI를 없애거나 "더보기" 뒤로 숨기는 것을 최우선 검토. 나머지(난이도/톤/실무연계)는 유지하되 한 화면에서 시각적 위계를 낮추는 것도 고려.

### P-2. 완료 화면(SessionCompleteScreen) 조건부 블록 9종 과밀 — **확신도: 상**
**원래 의도**: XP(F-37), 자기최고기록(F-41), 스트릭위기(F-42), 깜짝보상(F-39), 뱃지(기존), 정체성서사(F-22, 마일스톤 한정), 컨페티(F-40)는 각각 "완료 순간의 행복감"을 높이려는 독립적 시도였고, `feature_definition_engagement.md`도 이 문제를 **이미 §1 "구조적 이슈"로 예견**하고 "노출 우선순위/최대 노출 개수 규칙을 구현 단계에서 정해야 한다"고 명시했었다.
**재검토 사유**: 실제 코드(`SessionCompleteScreen.tsx`)를 확인한 결과, 그 규칙이 구현되지 않은 채 레벨업 블록·XP 카운트업·성장피드백·프리즈안내·깜짝보상·마일스톤 정체성서사·뱃지 목록·공유 버튼 2개가 조건 충족 시 전부 동시에 쌓일 수 있는 구조 그대로 배포됐다. 자동 이동 타이머(4초/6초, 레벨업 시 +2초)도 이 콘텐츠 양과 무관하게 고정 발동돼 "5분 완결" 원칙상 사용자가 다 읽기도 전에 화면이 넘어갈 위험이 여전하다.
**권장 방향**: 계획 문서가 이미 제안한 대로 "그날 가장 중요한 이벤트 1~2개만 강조 노출, 나머지는 조용히 생략"하는 우선순위 로직을 지금이라도 구현. 우선순위 예시: 레벨업 > 자기최고기록 > 뱃지 > 나머지.

### P-3. 오답 다시풀기 / 내 문제집(북마크) / 오답 목록 — 3화면 중복 재검토 — **확신도: 중**
**원래 의도**: 오답 목록(F-13, 자동 수집), 오답 다시풀기(F-13 확장, 반복 출제), 내 문제집(사용자 수동 북마크)은 각각 "자동 복습"과 "사용자가 직접 고른 것 모아보기"라는 다른 가치를 준다는 게 설계 의도였다.
**재검토 사유**: `WrongPoolScreen`, `RetryWrongScreen`, `MyQuestionBookScreen` 3개 파일을 실사한 결과 UI 골격(목표별 섹션 → 카드 리스트 → 질문/정답/해설)이 사실상 동일하고, `SettingsScreen`에는 "오답 목록 보기" / "내 문제집 보기" / "녹음 모음 보기" 3개 링크가 나란히 나열돼 있다. 사용자가 "오답"과 "북마크"의 차이를 즉각 구분해서 각각 다른 목적으로 쓸지는 실사용 데이터 없이 단정하기 어렵다. 두 리스트를 하나의 화면에서 탭(오답/북마크) 전환으로 통합하면 화면 수(2개 → 1개)와 설정 메뉴 항목이 줄어 혼동 가능성이 낮아진다.
**권장 방향**: 단정하지 않음 — FO 단계에서 실사용 로그(오답 목록 vs 내 문제집 방문 빈도)를 먼저 확인한 뒤 통합 여부 결정 권장.

### P-4. 확률적 깜짝 보상(F-39, `surpriseReward`) — **확신도: 중**
**원래 의도**: 세션 완료 시 낮은 확률(20%)로 비화폐성 격려 카드를 노출해 "예측 불가능한 긍정적 자극"을 주려는 의도였고, 계획 단계에서도 "가챠·수집형 인벤토리로 확장되지 않도록" 스스로 제한을 걸어뒀다.
**재검토 사유**: 제한 장치를 잘 걸어뒀다는 점은 확인되나, "확률적으로 보상을 준다"는 구조 자체가 이 앱의 정체성("공부해야 하지만 게으른 사람"을 돕는 담백한 도구)과 잘 맞는지는 별개 문제다. 정답을 맞혀서 받는 보상(뱃지, XP)과 달리 순전히 운으로 받는 보상은 핵심가치("포기 안 하게")에 기여하는 경로가 간접적이고, 완료 화면 과밀(P-2)에도 한 블록을 더 보태고 있다.
**권장 방향**: 재검토 필요. 제거하거나, 완료 화면이 아닌 다른 저빈도 접점(예: 마일스톤 시점에만)으로 옮기는 것도 고려.

### P-5. AI 학습메이트 톤 3종(`mateTone`) 인프라 전체 재검토 — **확신도: 하**
**원래 의도**: 20대 세그먼트 리서치(F-27)에서 페르소나 기반으로 도출된 기능이며, 이후 알림(F-30)·마스코트(F-38)·스트릭 위기 문구(F-42)까지 같은 톤 축을 계속 재사용하며 인프라가 정당화돼 왔다.
**재검토 사유**: 재사용성이 높다는 것 자체는 좋은 설계이지만, 거꾸로 보면 "톤이 실제로 거의 안 쓰인다"는 가정 하에서는 뱅크 3배, 마스코트 표정 3종, 위기 문구 3종 전체가 다 함께 유지보수 부담이 된다. 확신을 갖고 결론 내리기엔 실사용 데이터(기본값 `plain` 대비 `friendly`/`hype` 선택 비율)가 없다.
**권장 방향**: 단정하지 않음 — 반드시 실사용 비율을 먼저 확인한 뒤 판단. 만약 90% 이상이 기본값을 쓴다면 톤 선택 UI는 유지하되 후속 확장(신규 톤 추가 등)은 동결 권장.

### P-6. 하단 탭에서 "업적"이 핵심 내비게이션과 동급 배치 — **확신도: 중**
**원래 의도**: 게임화 테마(F-35~F-42) 도입 당시 뱃지·업적을 상시 눈에 띄게 해 동기부여 효과를 극대화하려는 의도로 보인다.
**재검토 사유**: `BottomNav.tsx` 실사 결과 하단 탭은 정확히 4개 — `홈` `목표` `업적` `설정` — 이며 이 중 "업적"만 핵심 학습 루프(목표 생성→학습→테스트→완료)와 무관한 순수 동기부여/진열장 화면이다. "게으른 사용자"가 앱을 열 때마다 보는 4개 탭 중 1개가 학습 자체가 아니라 "그동안 모은 뱃지 구경하기"인 것은, 화면 배치의 무게중심이 조금씩 게임 요소 쪽으로 기울고 있다는 신호일 수 있다.
**권장 방향**: 재검토 필요. 업적을 하단 탭에서 빼고 설정 화면이나 홈 화면 내 작은 진입점으로 격하하는 안, 혹은 유지 여부는 실사용 탭 클릭 빈도를 보고 판단 권장.

### P-7. 녹음 모음(음성 답변 녹음, F-46 추정) — **확신도: 하**
**원래 의도**: 커밋 로그(`음성 답변 녹음 기능 추가`)로 미루어 학습 중 자기 답변을 육성으로 남기는 기능으로 추정되나, 어떤 기능정의서에도 목적·페르소나·검증 조건이 문서화돼 있지 않다.
**재검토 사유**: "5분 완결"이 핵심인 앱에서 오디오 blob을 녹음·저장·재생·삭제까지 지원하는 화면(`RecordingsScreen.tsx`)은 핵심 학습 루프(요약→퀴즈→피드백)에 직접 기여하는지 불분명하고, 1인 개발자가 오디오 저장소(브라우저 저장 공간, 재생 URL 정리 등)까지 계속 떠안아야 하는 기능이다. 문서화가 아예 안 됐다는 사실 자체가 "충분히 검토되지 않고 만들어졌을 가능성"의 신호이기도 하다.
**권장 방향**: 단정하지 않음. FO가 이 기능의 원래 목적을 먼저 역추적하고(어떤 요청/근거로 만들어졌는지), 실사용 빈도를 확인한 뒤 유지·축소·제거를 결정할 것을 권장.

### P-8. 학습 캘린더의 히트맵 성격 — **확신도: 하**
**원래 의도**: 시험일/마감일을 한눈에 보여주는 실용적 목적(F-33/F-29 연계)으로 도입.
**재검토 사유**: 실사 결과 `CalendarScreen.tsx`는 마감일·시험일 표시(실용적, 문제없음)와 함께 "학습 완료한 날짜 히트맵"(월 단위 초록 점)도 함께 보여준다. 이는 "심층 통계/학습 패턴 분석은 Non-goal"이라는 F-06/F-16 원칙의 경계에 가깝다. 아직 "심층"이라 부를 수준은 아니라 명백한 비목표 위반은 아니지만, 앞으로 여기에 요일별 통계 등이 얹히기 시작하면 위험하다.
**권장 방향**: 현재 수준은 유지하되, 이 화면에 새로운 통계 지표를 추가하는 시도는 비목표 침범으로 보고 제동을 걸 것을 권장(가드레일 성격의 기록).
