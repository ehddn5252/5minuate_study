# 5분 학습 — 재미/행복감(Engagement) 기획 문서 (v1.0)

> 작성 주체: Planner Agent
> 작성일: 2026-07-06
> 성격: 연령대 세그먼트 축(30대/20대/10대)이 아니라 **테마 축(애니메이션·게임 메커닉·정서적 행복감)**을 다루는 별도 문서. 페르소나 대신 "지금 코드 기준으로 재미가 비어있는 지점"을 근거로 분석한다.
> 북극성: 소셜 랭킹 없이 Duolingo급 도파민/리텐션을 만든다.
> 다음 단계: 방향 확정 후 FO(Feature Owner) 에이전트가 구체적 기능 명세로 구체화.

---

## 0. 핵심 긴장 — 정면으로 다룬다

Duolingo의 핵심 재미 엔진 중 하나(리그/리더보드, 친구 경쟁)는 본 프로젝트의 비목표 "소셜 랭킹(친구 비교, 리더보드, 그룹 스터디) 금지"와 정면 충돌한다.

이 문서는 이 충돌을 얼버무리지 않는다. 방향 제안(§3)은 전부 **싱글플레이어 게임화**로만 구성했고, 그래도 남는 애매한 항목 하나는 §5에서 별도로 분리해 임의로 결정하지 않고 사람 승인 게이트로 넘긴다.

## 1. 문제 정의 — 지금 코드에서 "재미/행복감"이 비어있는 지점

코드를 직접 확인한 근거:

1. **정답/오답 피드백이 색과 텍스트뿐, 모션이 없다.**
   `src/components/QuizCard.tsx`의 피드백 블록(147~167행)은 `bg-green-50`/`bg-amber-50` 배경과 "정답입니다!" / "다음에 다시 나와요" 텍스트로 끝난다. 등장 애니메이션, 흔들림, 파티클 등 어떤 모션 처리도 없다.

2. **사운드·햅틱이 프로젝트 전체에 전무하다.**
   `navigator.vibrate`, `new Audio(...)`, `AudioContext` 를 프로젝트 전체에서 검색했으나 단 한 곳도 없다(음성 낭독 `src/utils/speech.ts`만 존재, 이는 정답/오답 피드백용이 아니라 F-25 오디오 학습 모드용). 정답을 맞혀도 "삐빅" 소리나 진동 하나 없다.

3. **콤보/연속 정답 개념 자체가 없다.**
   `src/screens/TestScreen.tsx`는 `answers` 배열(158~193행)로 정오답을 채점에만 사용할 뿐, 연속 정답을 카운트하거나 시각화하는 로직이 없다. Duolingo의 "콤보 보너스" 같은 순간적 고양감을 만들 지점이 비어있다.

4. **완료 화면의 유일한 축하 연출이 tailwind 기본 `animate-bounce` 하나뿐이다.**
   `src/screens/SessionCompleteScreen.tsx`(54행), `src/screens/GoalCompleteScreen.tsx`(44행) 모두 이모지 하나에 `animate-bounce`를 건 게 전부다. 색종이(confetti), 숫자 카운트업, 화면 전체를 채우는 축하 연출이 없다. `tailwind.config.js`는 `theme.extend: {}`로 완전히 비어있어 프로젝트에 커스텀 keyframes/모션 시스템 자체가 없다 — 즉 tailwind 기본 유틸(bounce/pulse/spin, opacity/transform transition) 밖의 모션은 아예 설계된 적이 없다.

5. **뱃지 획득이 정적 그리드로만 표시된다.**
   `SessionCompleteScreen.tsx`(105~120행)의 뱃지 획득 UI는 아이콘+이름을 나열할 뿐, "잠금 해제" 순간의 등장 모션(예: 확대되며 나타남, 빛나는 효과)이 없다.

6. **XP/레벨 개념이 데이터 모델에 아예 없다.**
   `src/types/index.ts`의 `Goal`, `AppState` 어디에도 xp·level 필드가 없다. 진행 신호는 정답률(%)과 스트릭(연속 일수)뿐이라, "포인트가 쌓이고 있다"는 누적 성장의 감각이 약하다.

7. **감정을 표현할 캐릭터(마스코트)가 전혀 없다.**
   전체 코드베이스에서 이모지(🔥, 🏆, 🎉 등)만 사용될 뿐, 사용자의 정오답·스트릭 상태에 반응하는 캐릭터 개체가 없다. 기쁨/걱정 등 감정을 "누가" 표현하는지가 비어있다.

8. **스트릭 위기 상황의 긴장감 연출이 없다.**
   F-18 리듬 유지권(streak freeze) 사용 시 `SessionCompleteScreen.tsx`(89~95행)는 파란 정보 박스 텍스트로만 안내한다. "위기를 넘겼다"는 안도감을 강화하는 연출이 없다.

종합하면: 앱의 정보 전달은 촘촘하지만(스트릭, 진행률, 뱃지, 성장 피드백 모두 데이터로는 이미 존재), 그 데이터를 **감각적으로 체감시키는 계층(모션·사운드·캐릭터)**이 통째로 비어있다.

## 2. Duolingo 벤치마킹 — 재미 메커닉과 소셜 랭킹 의존 여부

| # | 메커닉 | 설명 | 소셜 랭킹 의존 여부 |
|---|---|---|---|
| 1 | 리그/리더보드(주간 랭킹, 승급·강등) | 다른 사용자와 XP를 겨루는 주간 리그 | **의존 (완전)** |
| 2 | 스트릭 + 스트릭 프리즈/복구 아이템 | 연속 학습일, 끊기면 아이템으로 복구 | 비의존 — 본 프로젝트도 이미 구현(F-18 리듬 유지권) |
| 3 | XP 획득 연출 + 레벨업 팝업 | 세션마다 포인트가 쌓이고 카운트업 애니메이션과 함께 레벨업 | 비의존 |
| 4 | 콤보/퍼펙트 레슨 보상(파티클·사운드) | 연속 정답 시 특별 연출, 만점 시 별도 축하 | 비의존 |
| 5 | 마스코트(듀오)의 감정 반응 | 정답/오답/스트릭 상태에 따라 표정·대사가 바뀌는 캐릭터 | 비의존 |
| 6 | 확률적 보상(보물상자 등) | 세션 완료 시 확률적으로 코스메틱·보너스 지급 | 비의존(화폐성 아님) |
| 7 | 친구 스트릭 공유/리마인드("찌르기") | 친구의 스트릭이 위험할 때 1:1로 알림을 보냄 | **의존(관계형, 그룹 랭킹은 아니지만 타인 존재 전제)** |
| 8 | 자기 최고 기록(Personal Best) 축하 | 개인 최고 정답률·최장 스트릭 경신 시 별도 축하 | 비의존 — 본 프로젝트 F-31 성장 피드백과 방향이 일치 |

8개 중 6개는 소셜 랭킹 없이도 구현 가능하며, 이 문서의 방향 제안(§3)은 전부 이 6개 축에서 나온다. §5에서 7번(관계형 리마인드)의 경계 사례만 별도로 다룬다.

## 3. 방향 제안 (6.1~6.8)

### 6.1 정답/오답 마이크로 인터랙션 강화
`QuizCard.tsx`의 피드백 블록에 등장 애니메이션(정답: 확산/바운스, 오답: 부드러운 흔들림)을 추가한다. 확률적 보상(6.5)·콤보(6.2)의 기반이 되는 가장 저비용·고임팩트 지점.
**소셜 랭킹 없이 구현 가능: 예.** tailwind 커스텀 keyframes 추가만으로 가능(신규 유료 의존성 불필요).

### 6.2 콤보(연속 정답) 시스템
`TestScreen.tsx`의 `answers` 배열을 활용해 연속 정답 카운트를 계산하고, "3연속 콤보!" 같은 순간 피드백을 문항 사이에 노출한다.
**소셜 랭킹 없이 구현 가능: 예.** 완전히 로컬 상태 계산.

### 6.3 XP/레벨업 연출 도입
`Goal`/`AppState`에 xp 필드를 추가하고, 세션 완료 시 카운트업 애니메이션 + 레벨업 시 풀스크린 축하를 넣는다. 기존 스트릭·정답률과 별개로 "쌓이는 감각"을 만든다.
**소셜 랭킹 없이 구현 가능: 예.** 순수 개인 누적치, 타인과 비교하지 않음(랭킹 노출 금지를 명시적 제약으로 못박아야 함).

### 6.4 마스코트 캐릭터 도입
정답/오답/스트릭 위험/완료 시 표정이 바뀌는 캐릭터(이모지 조합 또는 경량 SVG)를 도입한다. 기존 `mateTone`(F-27: friendly/hype/plain)과 결합해 캐릭터의 말투·반응 강도도 함께 분기한다.
**소셜 랭킹 없이 구현 가능: 예.** 신규 이해관계자(타인) 없이 개인-캐릭터 관계로 완결.

### 6.5 확률적 보상(비화폐성 "깜짝 보상")
세션 완료 시 확률적으로 격려 카드, 뱃지 프리뷰, 테마 색상 잠금 해제 등 비화폐·비페이월 보상이 열리는 연출을 추가한다. 러닝박스(뽑기 결제)와 달리 지급만 있고 구매 유도가 없다.
**소셜 랭킹 없이 구현 가능: 예.** free 예산 제약과도 상충 없음(가상 재화만).

### 6.6 완료 화면 축하 연출 확장(컨페티+카운트업+햅틱+사운드)
`SessionCompleteScreen.tsx`/`GoalCompleteScreen.tsx`의 `animate-bounce` 하나뿐인 축하를 canvas 기반 경량 컨페티(외부 유료 라이브러리 아님, 직접 구현), `navigator.vibrate` 햅틱, Web Audio API로 직접 생성한 짧은 효과음으로 확장한다. 모두 opt-out 가능해야 한다(조용한 틈새 시간 사용자 고려 — 10대 세그먼트 문서 §5와 결이 같음).
**소셜 랭킹 없이 구현 가능: 예.**

### 6.7 "자기 최고 기록 갱신" 축하 강화
`src/utils/growthFeedback.ts`(F-31)를 확장해 개인 최고 정답률·최장 스트릭 경신 시 일반 성장 피드백과 구분되는 강한 축하 연출을 별도로 넣는다. 이미 "랭킹이 아닌 자기 이력 비교" 원칙과 완전히 일치하므로 확장 리스크가 가장 낮다.
**소셜 랭킹 없이 구현 가능: 예.**

### 6.8 스트릭 위기 상황의 감성 연출
F-18 리듬 유지권 소진 임박(잔여 0) 및 사용 시점에, 마스코트(6.4)가 안도/걱정 표정을 짓는 연출을 추가한다. 단, `notification.ts`의 F-20/F-30 "동행형 톤" 원칙을 유지해 압박형으로 변질되지 않도록 톤 검증이 필요하다.
**소셜 랭킹 없이 구현 가능: 예.** (단, 기존 "압박 아닌 동행" 톤 원칙과의 정합성 검토는 FO 단계 과제로 남김.)

## 4. 고려했으나 제외한 방향

| 방향 | 제외 사유 |
|---|---|
| 리그/승급·강등 시스템 | 소셜 랭킹 그 자체 — 비목표 정면 위반 |
| 친구 목록/그룹 챌린지 | 소셜 그래프 형성 — 비목표 위반 |
| 실시간 퀴즈 대전(1:1 배틀) | 소셜 기능이자 실시간 인프라 비용 발생 — free 예산 위반 소지 |
| 유료 캐릭터 스킨/코스메틱 판매 | free 예산 제약 위반 |
| 광고 기반 보상형 뽑기 | 규제/약관 검토가 필요한 새 영역, 범위 밖 |
| 장문 스토리형 캠페인(챕터식 내러티브) | 콘텐츠 제작 비용이 크고, 긴 세션 최적화로 흐를 위험 — "5분 완결" 원칙과 충돌 우려 |
| 사운드·진동 강제 ON(끄기 불가) | 학교·학원 등 조용해야 하는 틈새 시간 사용 맥락(10대 세그먼트 등)과 충돌 — 반드시 opt-in/opt-out 가능해야 함 |
| 심층 성장 그래프/통계 대시보드 | 심층 분석 대시보드 비목표와 경계 모호 |

## 5. 비목표 재검토 후보 — 사람 승인 필요 (임의 결정하지 않음)

**항목: 친구/보호자 1:1 스트릭 리마인드("찌르기")**

- **왜 후보에 올렸는가:** Duolingo에서 친구의 스트릭이 끊길 위기일 때 1:1로 알림을 보내는 기능은 리텐션 효과가 검증된 메커닉이다(§2의 #7). 본 프로젝트에도 이미 F-34 공유 카드(보호자/친구용, `src/utils/shareCard.ts`)가 "앱 밖 공유"로 한 방향(사용자 → 타인) 존재하지만, "찌르기"는 **타인이 사용자에게 다시 보내는 양방향 상호작용**이라는 점에서 질적으로 다르다 — 이는 리더보드나 그룹 비교가 아니지만, 앱 안에 "타인의 존재"를 새로 들여오는 것이므로 "소셜 랭킹 금지" 비목표의 정신(사회적 비교·경쟁 압박 배제)과 얼마나 가까운지 판단이 갈릴 수 있다.
- **내 판단(참고용, 결론 아님):** 랭킹·비교가 없는 순수 응원 메시지라면 비목표 위반은 아닐 가능성이 높다고 보지만, (1) 상대방 식별/연결 수단이 필요해 기존에 없던 "관계 데이터" 저장이 발생하고 (2) 향후 그룹 기능으로 확장될 유혹이 생길 수 있어, **임의로 착수하지 않고 승인을 받는다.**
- **대안(승인 없이 갈 수 있는 경로):** §3.6~3.8(확률적 보상, 자기 최고 기록 축하, 스트릭 위기 감성 연출)만으로도 "스트릭을 지키고 싶다"는 도파민의 상당 부분을 싱글플레이어로 재현할 수 있다고 판단한다. 즉 이 항목이 없어도 핵심 재미가 완전히 죽지는 않는다.
- **요청:** 이 항목은 **착수 보류**. CEO 승인이 있을 때만 FO 단계에서 구체화한다.
